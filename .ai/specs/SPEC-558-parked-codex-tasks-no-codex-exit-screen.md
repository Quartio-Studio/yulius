## Decisions

An achieved live owner with a recorded failed singleton keeps its session slot and its chained successor until the hosted pull request verifies that the decision is obsolete. Capacity reads stay local. A later arm or changed delivery invalidates an in-flight completion check. A rule waiting for all tasks includes unverified owners. Compound rules keep the relevant merge writers through successor admission. A close based on Done rechecks its owner under the same writer.

An automatic continuation for a parked PR owner verifies the recorded integration decision before launching. A human decision or unavailable capacity leaves the original session parked. The next watcher pass checks the PR again before delivering a prompt.

Parking and a replacement merge request share the task’s merge writer at admission. If the writer is busy or a merge is armed, the idle pass leaves the session live. Once the park commits, a new merge request checks the committed run and durable task state before it can arm. Stop, close, or loss can settle that same run and release its park marker. Final admission checks the attached attempt while holding the end-intent lock. An exit reader already settling the run takes precedence over an earlier idle observation.

A named Continue checks the current model and the requested subscription when Yulius accepts the start or queue entry. A refusal preserves the resting state, archive and question. The queue checks availability again at dispatch through its existing subscription policy. An immediate launch uses the model and account admitted together.

An owner can stop a task while its previous run is still finishing a park. Continue waits for that run's terminal cleanup before entering the queue or starting again. A settlement timeout or a refusal because the previous run is still live leaves the archive and outstanding question available for retry. The owner can also archive or close a replacement turn during admission. The start or queue claim checks the original attempt, archive and status together with the change that accepts the continuation. A remote restart keeps its first selection through the permission check. A goal resume waits for terminal cleanup under the same bound. Direct resume, including onboarding, carries the resting selection through acquisition of the launch lock. A replacement attempt must settle under its own admission check. Answering the question records the timestamp of acceptance.

Capture a separate screen at the park decision because exiting can clear the entire alternate screen. Changing shutdown signals would couple presentation to the harness and could interfere with reaping. A separate snapshot lets an unsuccessful park keep its real terminal. Reuse native Codex resume and the Stop hook's persisted three-block budget. Older runs can only recover content still present in their saved screen. A parked owner terminal fits the saved grid to the viewport so the first row, last row and notice survive a smaller window. If the PR is the only remaining work and the Stop lookup cannot finish, the continuation asks the agent to verify its checks. Parking reads the current head before acquiring the launch lock and supplies that signal to the final eligibility check.

A human request can take precedence over unfinished work in the task list. Both parking triggers therefore check the recorded plan, spec and native goal immediately before committing to shutdown. The task’s steps lock orders that decision with plan, spec and goal updates. An update in progress or a store read failure leaves the session live for a later pass.

The scheduler discards older completed verdicts for a head after a later run was refused because the integration configuration was invalid and that configuration has since been repaired. A fresh queued run covers the repair. The scheduler reads the 200 most recently admitted records through a sandbox index so a superseded queue position cannot reverse the history.

Yulius CI schedules one run per commit even when two PRs publish the same head. The queue and `yulius wait` prefer the owner’s own ordinary run when one exists. Otherwise they use the run that covers that commit under the scheduler’s rule. An ordinary integration configuration refusal invalidates earlier completed results for every PR at the commit. Active owner runs and explicit owner cancellations retain their meaning. A cancellation of a different reference cannot lend a verdict. Queue decisions and merged receipts use the full object name supplied by Git or the host. The wait endpoint also accepts a unique abbreviation. GitHub still enforces its required commit status when the queue submits the merge.

A failed singleton can reuse the tested tree of a candidate with several members. The live queue verifies the PR’s hosted head and base in one lookup and attributes the failure to the member it decided. Restart recovery needs a durable decision written together with consumption of the original arm. A best-effort timing span cannot supply that guarantee. An ordinary owner rerun keeps its existing deadline. An unavailable or partial hosted read, an unreadable ordinary CI record at the exact PR head, or unavailable failure or redaction data retains the candidate and its original ordinary wait deadline. A continuous verification outage beyond the 15-minute merge wait lets the same arm proceed one by one. The owner message uses retained test failures or the failing job’s structured reason, redacts before and after formatting, and bounds the excerpt. A vanished source run cannot consume the arm. The queue consumes a confirmed arm at its final ordinary CI observation before writing the dissolution audit.

The hourly telemetry cleanup retains the latest merge wait for each existing task. A long-lived arm can start before the 180-day cutoff and reach a decision just before cleanup. Keeping one decision allows recovery to identify the consumed activation. An ordinary verdict that follows a singleton must also be retained. Select by activation time and then row id, as the latest wait can be inserted before a delayed older one. Removing a task releases this retention exception.

The queue writes the accepted singleton to the owner’s completed merge wait before releasing the original arm. The receipt carries the redacted reason and exact tested inputs. A reviewed head move preserves its activation time. A new request saves a strictly later activation before retiring the earlier receipt. The queue verifies retirement against the observed row and detail before taking the replacement. A direct merge or already-merged retry also reconciles pending retirement. Unreadable evidence leaves the saved request available to the next pass. The subsequent watcher slice must confirm the current holder and its members independently of a cached source run before sending instructions.

When the watcher sees an open PR during an active queue decision or its slot changes during the read, it supplies the PR number to the normal notice bookkeeping and defers events, check-ins and stalls for that pass. A subsequent recorded merge remains eligible for delivery once to the same task.

A live PR notice that finds the terminal writer busy leaves its event unheard. The existing bounded watch reevaluates the owner and event on its next pass. Once the first paste is accepted, the normal submit path completes it.

The live watcher resolves ordinary CI for the owner at the armed head and reads the active train’s recorded membership. Before delivering advice, it verifies the published head, the current queue request, its CI observations and the original recipient. A human decision or unverifiable observation leaves the event pending.

The final parking check compares the owner’s saved singleton decision with the verified PR head and integration base. A change to the saved merge decision during hosted verification defers the pass. A changed base or published repair retires the old failure for this decision.

The SQLite query returning a parked task includes the latest attempt ID in the same snapshot. Admission checks that ID under the launch lock after caller preflight. A message can wait while another turn resumes and parks, so task status alone cannot identify the session the sender observed. Only a matching parked attempt can restore Codex lineage or accept the prompt. Bulk messages, Telegram replies and remote restarts carry the attempt from their first task lookup through dispatch. They check the caller’s current access before acting.
