# 0423. A webpage copy returns through the clicking viewer’s connection

## Status

Accepted for [SPEC-584](../../.ai/specs/SPEC-584-in-browser-i-clicked-copy-button-but-not.md).

## Context

Webpages can copy text without selecting anything. Chromium writes it to the private virtual display’s CLIPBOARD selection. Several people can watch this display and each has a separate device clipboard.

## Decision

Observe a fresh CLIPBOARD ownership change following a viewer’s primary press on the sandbox display. Use a short-lived X selection requestor for that gesture and return UTF-8 text through the initiating viewer’s socket. Bound the transfer by the existing clipboard limit. Offer an explicit local copy gesture if the browser refuses the automatic write.

## Alternatives

Reading the DOM selection misses text generated by a button. Reading the current clipboard on every click would copy old contents. Forwarding every clipboard change to all viewers would overwrite other people’s clipboards.

## Consequences

The display can observe native clipboard writes made by the page or its frames without modifying their JavaScript or granting sites clipboard-read permission. The headless development backend has no private X display. It retains the keyboard selection path.
