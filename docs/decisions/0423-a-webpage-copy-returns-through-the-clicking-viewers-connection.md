# 0423. A webpage copy returns through the clicking viewer’s connection

## Status

Accepted for [SPEC-584](../../.ai/specs/SPEC-584-in-browser-i-clicked-copy-button-but-not.md).

## Context

Webpages can copy text without selecting anything. Chromium writes it to the private virtual display’s CLIPBOARD selection. Several people can watch this display and each has a separate device clipboard.

## Decision

Observe a fresh CLIPBOARD ownership change following a viewer’s primary press on the sandbox display. Send that connection a short-lived offer containing only an identifier. Accepting the offer prompts the X selection requestor to read UTF-8 text. Only the offering socket can accept it, once, while the selection is current. Bound the transfer by the existing clipboard limit. A local write refusal offers a native copy gesture.

## Alternatives

Reading the DOM selection misses text generated by a button. Reading the current clipboard on every click would copy old contents. An X ownership change carries no identity for the webpage, viewer or agent that caused it. Automatically transferring a nearby write could overwrite a device clipboard with unrelated text.

## Consequences

The display can observe native clipboard writes made by the page or its frames without modifying their JavaScript or granting sites clipboard-read permission. The headless development backend has no private X display. It retains the keyboard selection path.
