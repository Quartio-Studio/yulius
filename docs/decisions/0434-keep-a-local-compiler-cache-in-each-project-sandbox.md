# 0434. Keep a local compiler cache in each project sandbox

## Status

Accepted for the Yulius repository launcher and its disk upkeep. The launcher landed in [PR #1617](https://github.com/Quartio-Studio/yulius/pull/1617). Delivery and runtime measurements are recorded in [SPEC-595](../../.ai/specs/SPEC-595-share-compiled-rust-across-worktrees-and.md).

## Context

The operator measured 195 s compiling and 151 s testing in one CI shard. Each checkout retained 18–22 GB of Cargo output. A task, an independent CI run and the merge train can build the same revision at three different absolute paths. CI accounts CPU and cancellation to each job. Many tests open fixtures relative to the compile-time value of `CARGO_MANIFEST_DIR`.

## Decision

Bootstrap the pinned mbx 1.30.0 Linux executable and verify its release archive against the repository's SHA-256. The project Cargo launcher uses one content-addressed store at `<sandbox>/rust-compile-cache` on the existing sandbox mount. Agent and CI homes can differ. Each invocation starts its own local cache session and runs the compiler in the calling job. Cargo keeps its ordinary checkout-local targets. The xtask launcher embeds its checkout path and costs about 0.6 s to build from scratch, so scripts/dev starts it with pinned Cargo as before. Cached artifacts are verified and restored as private copies on the instance's ext4 filesystem.

Preserve the compiler's original workspace-root and `OUT_DIR` paths. mbx normalizes paths in lookup keys where possible and tracks literal inputs such as `env!("CARGO_MANIFEST_DIR")`. We disable its optional workspace source-path remapping because it also changes `file!()` and panic locations. For absolute Rust source arguments, and the compiler working directory when debug information is enabled, an identity prefix mapping adds the literal path identity to mbx's key. Rust maps that prefix to itself. Registry sources used from different Cargo homes and debug builds in different source directories therefore keep their original paths. Build scripts execute normally. Rust does not track arbitrary file or environment reads during procedural macro expansion. The compiler launcher bypasses the cache for a macro consumer and its dependents, including macros re-exported through ordinary libraries. For each Cargo invocation it records which Cargo-produced rlibs and metadata have a known macro-free dependency closure. Pre-existing externs without that proof compile directly. The cache session disables nonportable incremental output. An explicit `CARGO_INCREMENTAL=1` selects plain Cargo with its private incremental directory, which agents can use for an edit/build loop. An accessible foreground terminal and inherited Make jobservers also select plain Cargo. This preserves reads from `/dev/tty` with redirected stdin and the caller’s parallelism limit. Yulius’s unattended jobs identify their CI run and redirect all three standard streams. They use the cache in the original runner session and job cgroup so cancellation reaches the compiler. The logs distinguish these bypasses from the cache's hits, misses and initially unknown keys.

Give the store a 16 GiB collection budget. mbx's disk upkeep evicts old entries after builds, with at most one scheduled collection per minute. Concurrent writes can temporarily exceed the budget. Yulius's five-minute instance upkeep clears a marked, idle store above 20 GiB of allocated space if a CI job ended before collection. The launcher publishes the stamped directory with one rename. The stamp is the ownership contract for both builds and reclamation. Under quota or critical host pressure, Yulius can reclaim the idle store's contents after pruning other rebuildable output. Upkeep opens the marked directory once, measures allocated blocks through it with the sandbox quota walker, and counts hard links once. It moves the verified ownership stamp to a pending name and syncs the directory before clearing entries through the same handle. The ready stamp returns after successful cleanup. Older worktrees also use plain Cargo while the ready stamp is absent. A healthy-disk round resumes an interrupted removal. Pressure accounting conservatively excludes blocks of multiply linked files because names outside the store can keep those blocks allocated. Builds take a shared lock on the sandbox directory and pressure reclamation takes it exclusively without waiting. A new build during reclamation proceeds directly through Cargo. The Cargo dispatch closes the lease before running user code. A termination signal to the launcher stops the cache command and its process group and escalates after three seconds. The ordinary sandbox quota includes the bytes in the store.

Upkeep refreshes sandbox quota usage when it clears a cache, including a store with zero credited bytes. A task refused for exceeding quota gets one admission retry after that refresh. When another hard link still holds the sandbox over quota, the refusal stands. CI reads the refreshed usage before admitting waiting jobs.

## Alternatives

- **sccache 0.19.0.** In a two-checkout experiment with Rust 1.99.0, the same non-incremental library and fresh targets, the first build took 2.39 s and the second 1.60 s. Both roots were listed in `SCCACHE_BASEDIRS` and remapped in rustc's arguments. Both cacheable requests missed. The released Rust key hashes the compiler working directory and Cargo environment literally. Its single local storage server can serve concurrent clients, but its client-side mode still has those key semantics.
- **A shared dependency target.** Cargo has one mutable fingerprint and build-script tree. Using one target across worktrees takes its build lock across compilation. Copying or rotating it requires a publication and invalidation protocol and must preserve embedded paths.
- **Cargo's build cache on the pinned toolchain.** Stable Cargo 1.99 can move intermediate outputs with `build.build-dir`. Two concurrent builds with separate targets and one shared build directory confirmed the lock. The first waited for a signal in its build script, the second reported a build-directory lock wait, and both exited 0 after release. On the pin, `cargo -Z fine-grain-locking metadata` refused the nightly-only option. Sharing that directory would serialize independent CI jobs.

## Measurements

On the instance, a lane-layout replay at `52b59ecb3` used two detached checkouts, independent empty targets and an initially empty private disk store. Both ran `scripts/cargo check --locked --offline -p yulius-domain --lib` with two Cargo jobs. The first lane took 9.49 s and populated 12 compilations. The second took 4.58 s and served every lookup (12/12). Across all compiler invocations the warm rate was 12/22 (54.5%), including seven mbx bypasses and three additional direct invocations for unknown or macro inputs each time. The cache copied 13.5 MiB to the warm target. No other build wrote this store.

The full worktree comparison used the pinned Rust 1.99.0 toolchain on the instance. At `52b59ecb3`, each command had a dedicated sandbox store. A cold checkout populated it and a second checkout of the same commit used it from another absolute path. Each had an empty Cargo target and used the same Cargo and rustup homes. Timings exclude bootstrap. Cargo and nextest each had 19 workers. Checks and tests overlapped each other, mutation testing and other instance work.

Both `scripts/dev checks` runs passed. Cold took 754.29 s and warm took 807.27 s. Of 424 eligible warm compiler requests, 403 hit, 11 missed and 10 lacked a prior key. That gives 95.0% reuse of eligible requests and 403/777 (51.9%) of all reported requests. There were 50 mbx bypasses and 303 additional direct invocations on each run. The warm macOS check took 192 s against 269 s cold. The native workspace check and lint took longer under the warm run's concurrent load. Across the complete checks command, warm took 52.98 s longer despite the avoided compilations.

Cold `scripts/dev test` took 1,160.11 s. Nextest finished in 908.38 s with 5,753 of 5,754 selected tests passing. A terminal flag assertion failed, stopping the command before doctests. The cold run had zero hits in 248 eligible requests (four misses and 244 initially unknown). Its pending doctests passed separately in 142.25 s with plain pinned Cargo. Warm `scripts/dev test` passed in 1,003.30 s, including all 5,754 selected tests and doctests. Nextest took 665.75 s. The warm worktree reused 222/248 eligible requests (89.5%) with nine misses and 17 initially unknown. Across both warm Cargo invocations it reported 222/445 hits (49.9%), including 79 mbx bypasses and 118 direct compiler runs. The test build itself took 246 s cold and 305 s warm, so these full-command wall times also reflect substantial variation in test execution and host load. [Terminal test issue #1615](https://github.com/Quartio-Studio/yulius/issues/1615)

A second, sequential test pair at the independently approved launcher `7fe27a3d6` ran from a new store and two empty targets with the same 19-worker limits. Cold took 854.69 s and warm took 593.92 s. Cargo's test build took 337 s and 196 s respectively. Each ran 5,752 tests and failed one unrelated assertion before doctests. The failures involved the stopped-run attention state on cold and loopback port release on warm. Cold served zero hits and warm served 222/248 eligible requests (89.5%), or 222/431 across all invocations (51.5%). [Stopped-run issue #1611](https://github.com/Quartio-Studio/yulius/issues/1611) and [loopback issue #1620](https://github.com/Quartio-Studio/yulius/issues/1620).

In the first physical PR and merge-train runs using the launcher, the six existing lane targets reported **zero shared hits**. Each run had 27 eligible compiler requests across quality and the two test jobs. Cargo already had local intermediates, and the launcher compiled consumers with unproven or macro dependencies directly. The clean-target lane replay and worktree numbers describe a different starting state. Across consecutive physical dev merge trains the gate took 866 s before and 812 s after. The observed job durations provide no evidence that cache hits sped up that train. [Scheduled jobs and counters in SPEC-595](../../.ai/specs/SPEC-595-share-compiled-rust-across-worktrees-and.md#scheduled-ci)

The later full merge train for PR #1618 served 15 hits in quality and nine in each shard. Across three lane checkouts, 33/65 eligible requests (50.8%) and 33/482 compiler invocations (6.8%) hit. It passed in 477 s. The scheduler and per-job counts are recorded in [SPEC-595](../../.ai/specs/SPEC-595-share-compiled-rust-across-worktrees-and.md#scheduled-ci).

## Consequences

A cold build pays for recording outputs and a warm build pays to validate and copy them. Tests still execute. The optional tool's absence or a cache startup failure leaves the ordinary Cargo command available. Repository CI and agent commands use `scripts/dev` and `scripts/cargo`. The project configuration leaves global Cargo installations alone. A different Rust project can adopt the launcher after measuring its own builds and agreeing on a sandbox disk budget.

The implementation and the path behavior are described in the upstream [mbx cache limits](https://mr-boxington.jdx.dev/limits), [sccache 0.19 Rust key](https://github.com/mozilla/sccache/blob/v0.19.0/src/compiler/rust.rs) and [Cargo build-cache reference](https://doc.rust-lang.org/cargo/reference/build-cache.html).
